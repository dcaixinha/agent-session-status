# AUR packaging

The stable `agent-session-status` AUR package is generated from
`PKGBUILD.template` when a non-prerelease GitHub release is published.
The workflow downloads the tagged source archive, inserts its version and
SHA-256 checksum, builds and tests the package in Arch Linux, generates
`.SRCINFO`, and pushes the resulting metadata to the separate AUR Git
repository.

## GitHub setup

Create a dedicated Ed25519 key for AUR automation, register its public key on
the maintainer's AUR account, and save the private key as the GitHub Actions
secret `AUR_SSH_PRIVATE_KEY`. The publish job uses the GitHub environment
`aur`, so that environment can optionally require manual approval.

```sh
ssh-keygen -t ed25519 -N '' -f ~/.ssh/aur-agent-session-status
# Add ~/.ssh/aur-agent-session-status.pub in the AUR account settings first.
gh api --method PUT repos/dcaixinha/agent-session-status/environments/aur
gh secret set AUR_SSH_PRIVATE_KEY --env aur \
  < ~/.ssh/aur-agent-session-status
```

The key is account-wide on AUR even though it is dedicated to this workflow;
protect the `aur` environment accordingly and revoke the key if the secret or
workflow is ever compromised.

The repository must be public before publishing a release because AUR users
must be able to download the tagged source archive.

## Release flow

Use the release driver from a clean, synchronized `main` branch after making
the repository public and configuring the AUR secret:

```sh
packaging/release.sh --dry-run 0.1.0
packaging/release.sh 0.1.0
```

For the initial release, the requested version may already match Cargo. For a
later version, the script updates `Cargo.toml` and `Cargo.lock`, runs all
release gates, and then creates the release commit. It atomically pushes `main`
and the annotated tag, publishes the GitHub release with generated notes, and
waits for the `Publish AUR` workflow. Pass `--no-wait` to leave AUR publication
running in the background.

The script is resumable: rerunning it can push a previously created local tag,
create a missing GitHub release for an already-pushed tag, or re-dispatch AUR
publication for an existing release. A failed version bump before its release
commit restores `Cargo.toml` and `Cargo.lock`. If additional commits have been
made since a release tag, retry AUR publication directly through the workflow
dispatch instead of moving or recreating the tag.

For a packaging-only correction, manually dispatch the workflow with the same
published tag and a greater `pkgrel`. The workflow never force-pushes AUR
history and treats an unchanged generated package as an idempotent success.

## Files published to AUR

- `PKGBUILD`, rendered from `PKGBUILD.template`
- `.SRCINFO`, generated by `makepkg --printsrcinfo`
- `LICENSE`, covering these packaging-source files under 0BSD

Application licensing remains documented in the upstream source archive.
